# Lucide Icons

## Overview

Use real Lucide icons (https://lucide.dev, ~1700 icons, ISC license) everywhere —
never hand-draw icon shapes, never guess icon names from memory.

**Core rule: an icon name is only valid if it appears in `references/icon-index.md`.**

## Resolving a concept to an icon

1. Grep `references/icon-index.md` (same directory as this skill) for the English
   concept word. Tags are official Lucide synonyms — search them, e.g. "cabbage"
   matches `leafy-green`.
2. The icon name is the **first column** of the matching line. Use it verbatim.
3. Multiple matches → pick the most literal one (`salad` beats `vegan` for a salad).
4. **No match → fallback, in this order:**
   - grep a broader/related English word (synonym, hypernym)
   - pick the nearest real concept (`cherry` for a berry, `package` for a parcel)
   - if nothing is semantically close, use a text label or a neutral icon
     (`circle-question-mark`, `tag`) — **never invent a name**

You may skip the grep ONLY for these evergreen names you can verify exist anyway:
`house, search, shopping-cart, shopping-bag, user, settings, bell, heart, star, plus,
minus, x, check, chevron-right, chevron-left, chevron-down, chevron-up, arrow-right,
arrow-left, menu, trash-2, pencil, eye, lock, mail, phone, calendar, clock, map-pin,
camera, log-out, info, circle-alert, circle-question-mark, share-2, download, upload,
layout-grid, grid-2x2, layers, package, funnel`

Lucide renames icons over time (`filter` → `funnel`, `home` → `house`,
`circle-help` → `circle-question-mark`, `edit` → `pencil`). If a familiar name is
missing from the index, grep for its concept — the new name will surface via tags.

## Figma output (via Figma MCP)

**Never construct icon `vectorPaths` by hand.** Get the real SVG source and insert it:

1. **Get the SVG source — outside `use_figma`:**
   - Preferred (always works, offline): read `references/icons/<icon-name>.svg`
     bundled in this skill (same directory as this SKILL.md).
   - Alternative, with your own HTTP/shell tool:
     `curl -sL https://unpkg.com/lucide-static/icons/<icon-name>.svg`
     (HTTP redirect — must follow).
   - No file-read tool AND no network (e.g. a session exposing only Figma tools):
     use the inline evergreen SVGs at the bottom of this skill — they are already in
     your context. If `references/icons-all.md` is attached to the conversation or
     project (it carries ALL ~1700 SVGs, one per line), search it for the name.
     Otherwise, for a non-evergreen icon, ask the user to paste the SVG; do not
     hand-draw.
   - **Do NOT call `fetch()` inside `use_figma`** — the Figma plugin sandbox has no
     network; `fetch` is `undefined` there. Resolve the SVG string first, then pass
     it in.
2. Theme it BEFORE insert: string-replace `stroke="currentColor"` with the design's
   color in the SVG source. (Setting strokes after insert also works, but must target
   the vector children — `createNodeFromSvg` returns a FRAME, not a vector.)
3. Insert: `figma.createNodeFromSvg(svgString)` inside `use_figma`.
4. Sizing: keep the native 24×24; scale with `node.rescale(targetPx / node.height)`
   (or set `width`/`height` in the SVG source before insert) — never redraw paths.
5. Consistency: one icon set per design (no Material/Feather/emoji mixing), one
   `stroke-width` everywhere (default 2; 1.5 for dense UIs).

## Code output

| Target | Package | Import name |
|---|---|---|
| React Native / Expo | `lucide-react-native` (+ `react-native-svg`) | PascalCase |
| React web | `lucide-react` | PascalCase |
| Plain HTML/CSS | `lucide-static` CDN SVG | kebab-case file |

PascalCase conversion: `shopping-cart` → `ShoppingCart`, `trash-2` → `Trash2`,
`a-arrow-down` → `AArrowDown`. Convert from a **verified** kebab-case name only.

Props: `size={24} color={theme.color} strokeWidth={2}` — theme via props, never edit
the SVG source. Type for dynamic icons: `import { type LucideIcon } from 'lucide-react-native'`.

## Red flags — STOP, you are about to repeat a known failure

| Thought | Reality |
|---|---|
| "I'll draw a simple home icon from paths" | Hand-drawn icons read as amateur. Fetch the real SVG. |
| "There's no design system to reference" | The icon set IS the reference — read the bundled copy in `references/icons/`, or fetch the CDN. |
| "I'll fetch the SVG inside use_figma" | The Figma plugin sandbox has no network — `fetch` is `undefined`. Get the SVG outside, pass the string in. |
| "No network and no shell available, so I'll draw it" | The SVGs ship WITH this skill — `references/icons/<name>.svg`. Read the file. |
| "I'm sure `Avocado` exists" | It doesn't. Baseline agents invented it. Grep the index. |
| "It's probably a newer icon, version caveat" | Confabulation. If it's not in the index, it does not exist. |
| "Close enough, `Vegan` for cabbage" | Tags exist for this — "cabbage" maps to `leafy-green`. Search tags first. |

## Common mistakes

- Guessing a PascalCase export and writing a "may not exist in your version" caveat
  instead of verifying — the index is the source of truth.
- Editing colors inside SVG path data instead of the `stroke` attribute.
- Mixing filled and outlined icon styles — Lucide is outline-only; for an "active" tab
  state change stroke color/width, don't switch to a filled icon from another set.

## Inline evergreen SVGs

Canonical Lucide sources for the evergreen names — for agents with no network and no
file-read tool. Replace `currentColor` with the design color before inserting.

A project-level skill may extend this block with its own domain icons (copy the
canonical SVG from `references/icons/<name>.svg` in the same minified format) —
agents with file access always have the full set in `references/icons/`.
